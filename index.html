A

Research Agent 是研究员

理解开放世界文本、选择获准工具、检索证据、提出事件与公司影响路径，但输出永远先是 Proposal。

不能做：

不能写权威账本、批准身份、计算权威涨幅或推进 checkpoint。

B

确定性内核是合规与会计

负责许可门、schema 校验、Quote Series 可比性、1/7/30 日计算、去重、发布、replay 与恢复。

不能做：

不能在缺证据时补造变量或替人作出关键判断。

C

人是最终签署者

确认当前实体、全局别名、报价序列、关键策略和高置信公司敞口；每次决策保留不可变记录。

不会做：

不会覆盖历史；新决定通过版本和重建改变当前有效状态。

商品候选 ≠ 权威观测

05 · CHEMICAL REASONING ENGINE

化工不是“涨价就利好”，而是一套分层身份、同口径价格与双向影响推理

首个 Investment Skill 是 chemical-capacity-barrier，但底层候选层对所有商品通用；化工特有逻辑留在领域 Skill 与验证器中。

产品族

它大体是什么

例如环氧树脂。只做聚合与导航，不把不同规格价格直接混算。

→
具体规格

它具体是哪一种

牌号、纯度、工艺路线、供应商等上下文共同确定身份。

→
报价序列

这组价格能否互相比较

产品、市场/企业、地区、币种、单位、税与运费口径必须一致。

显著变化

每个品种有自己的版本化触发策略

  • 同一 Quote Series 分别计算 1 日、7 日、30 日变化。
  • 同时超过最低绝对涨幅和自身历史波动阈值才视为显著。
  • 成熟品种使用历史分位数或波动率；新品种保守停在 L0。
  • 历史不足就显示 unknown，不能拿相似品种或另一地区补齐。
事件聚合

多篇材料形成一个版本化 Chemical Event

  • 每篇材料仍是独立、不可变的 Observation。
  • 按规格、报价序列、方向和时间窗口归并事件。
  • 独立来源数在事件层累积，新证据升级版本而不是重复 Alert。
  • Alert 按“事件 + 公司净敞口”去重。

生产商、下游、一体化与替代品必须分别建影响路径

可能正向

生产商

售价上涨是起点，还要扣除原料涨价、停产、低开工率和无可售增量。

关键变量：有效产能、外销量、价差、成本曲线
可能负向

下游企业

成本上升通常不利，但必须判断库存、合同定价、传导时滞和客户接受度。

关键变量：原料占比、库存成本、转嫁能力
计算净额

一体化企业

分别计算自产、自用、外采与外销量；同一轮涨价可能同时产生正负影响。

关键变量：自产覆盖率、内部结算、净敞口
需求迁移

替代品

比较性能、转换成本、认证周期与价差，判断需求是否真正迁移。

关键变量：替代弹性、切换周期、可用产能
泛化方式：共用候选与证据外壳，不创造万能本体。
化工：规格 · 工艺 · 价差 · 产能农产品：产区 · 品级 · 天气 · 库存金属：品位 · 交易所 · 库存 · 冶炼费能源：地区 · 热值 · 运输 · 期限结构

06 · END-TO-END JOURNEY

一条真实线索如何走到人工决策

  1. 成功摄入文本Signal OS 消费 source identity，不改变 raw/wiki 原有写入。
  2. L0 商品候选身份默认 unresolved，保留原词与证据位置。
  3. 人工确认当前提及只确认本篇，不自动创建全局 AliasRule。
  4. 结构化报价 Proposal经过 LicenseGate；认证材料与原始会员页不进入公开数据。
  5. 确认 Quote Series产品、规格、市场、地区、币种、单位、税运口径必须一致。
  6. Observation 与 Event历史不足时 1/7/30 日变化保持 unknown，不拼接不同序列。
  7. HypothesisV2 与 Alert公司证据不足就生成 evidence gap，而非硬判受益。
  8. Ask / Confirm / Wait / Ignore先 preview，再对精确 revision/digest 做人工 commit。
  9. Ask 研究交接只读 Agent 返回 Proposal 与检索引用，第二次人工操作才保存草稿。
  10. Checkpoint 与 replay完整发布才推进；同 source 重放不重复，失败进入 quarantine。

07 · CONCRETE EXAMPLE

用“三氯乙烯涨价”跑一遍完整脑内模拟

这个例子不是在推荐股票，而是在说明系统为什么要把名称、价格、事件、公司影响和决策拆成不同层。

用户或系统看到什么系统如何处理为什么不能跳步
专家会议提到“三氯乙烯近期涨价”成功摄入文本后进入 durable queue，提取一个 L0 名称候选并保存证据位置。文章里的词可能是简称、错别字、牌号或其他上下文实体。
用户确认本篇指的是既有三氯乙烯产品写入当前 mention 的不可变 resolution，候选可进入后续验证。只确认本篇；没有明确批准时不能把它变成所有材料通用的 AliasRule。
获准 Provider 返回常州或某企业日报价形成 rights-gated Proposal：产品、市场、日价格、涨跌值、单位和涨跌幅。认证材料与原始会员页不能进入产品账本，也不能因为页面能看就假定拥有所有保存权。
用户确认 Quote Series固定产品/规格、市场、地区、币种、单位、含税和运费口径。常州市场价、企业出厂价和另一单位的价格不是同一把尺子。
系统形成 VariableObservation查找同一序列的历史，计算可用的 1/7/30 日窗口；历史不足的窗口显示 unknown。不能拿相似产品、不同地区或另一规格补造涨幅。
多篇材料继续出现每篇保留独立 Observation，并归并到同一版本化 Chemical Event。新增证据应该提高事件证据，而不是制造一串重复 Alert。
原文说某生产商可能受益保存为 non-authoritative source claim，同时建立公司影响 Proposal 与 evidence gap。还要验证原料、停产、开工率、自产自用、外销量和下游传导。
AlphaAlert 建议 Ask人先预览 DecisionEvent，再确认 Ask；研究任务携带具体 gap、事件和公司 refs。Ask 只是“去找缺的证据”，不是“确认这家公司受益”。
Research Agent 找到公告、财报与行业引用返回只读 Proposal，可由人显式保存成待复核草稿，再决定 Confirm、Wait 或 Ignore。Agent 的语言再自信，也不能自动提升证据等级或覆盖历史决定。
同一 source 再次重放复用 source、quote、Event、Alert 与 Decision refs；完整记录可见后 checkpoint 保持一致。幂等 replay 是未来自动监听和失败恢复的前提。

08 · WHAT CHANGED

Stage 2 的六组核心变化

T37–T41 · 基础产品化

一根“装甲管道”连接 CLI、Desktop 和 Cockpit

  • 冻结一个版本化 headless application port。
  • Desktop 只接受封闭的 typed command，不复制业务逻辑。
  • 路径、参数、输出大小与超时都有边界。
  • Cockpit 获得只读状态、dry-run、单篇 replay、处理一篇、处理全部和 verify。
为什么重要

如果 CLI、UI 和 scheduler 各写一套编排，同一 source 会得到三种结果。现在它们只是入口适配器，真正的校验、计算和写入路径只有一份。

T42A / T42C · 决策权威

把“点过同意”变成可证明的精确签署

  • 所有写入先生成 DecisionEvent preview。
  • preview 固定 id、revision 与 contentDigest。
  • commit 在 single-writer 锁内重算；任何漂移返回 STALE_PREVIEW。
  • mention、Alert、Hypothesis 和公司敞口一次只处理一项。
  • 重启后由不可变决策重建当前 pending/decided 状态。
直觉解释

它像网银转账确认页：你签的是具体内容和具体版本，不是一个可能已经变化的标题。

T42B · QUOTE SERIES

让价格比较建立在同一把尺子上

  • Provider 报价先保持非权威 Proposal。
  • 人工确认产品/规格、市场、地区、币种、单位和税运口径。
  • 只有完全相同上下文才建议复用 Quote Series。
  • 所有历史窗口由确定性内核计算，数据不足保持 unknown。
  • 确认决定触发可重放的派生重建并对齐 evidence gap。
避免了什么错误

避免把企业出厂价与市场价、含税与不含税、吨与其他单位混在一起算出看似精确但没有意义的涨幅。

T43 · 真值优先

把“文章说利好”与“我们证明利好”分成两行

  • 提取公司 mention 与 source-stated impact claim。
  • 原文观点标为 non-authoritative source claim。
  • Cockpit 同屏显示“原文可能正向”和“公司净敞口 unknown”。
  • 公司证据不足时生成 company_exposure_unknown gap。
  • 有明确公司声称时，Alert 从泛泛 Wait 路由成具体 Ask。
为什么重要

“生产某产品”只是产业关系，不等于利润结论。售价、原料、产量、开工、内外销量和传导能力必须形成独立证据路径。

T45–T49 · 自动化就绪

为未来 scheduler 做恢复、安全与可观察性

  • bounded run-once、到期 retry 与 outbox 恢复。
  • 失败 source 进入 quarantine，后续 source 继续。
  • 调度摘要不暴露 Provider、原文或认证信息。
  • 加入生产角色 preflight、可逆调度管理和分阶段安全回归。
  • scheduler 永远不能代替人提交关键 DecisionEvent。
准确边界

“代码具备自动化基础”不等于“已经无人值守运行一周”。生产激活、登录过期恢复与耐久性仍必须单独验收。

ASK HANDOFF · 研究连续性

让 Ask 不再“点完就消失”

  • Ask 决策派生出持久可见的 evidence-gap 工作项。
  • 用户手动启动只读 Research Agent，不授予权威写入。
  • 第二次人工操作才保存 observation draft。
  • 重启后按精确 Alert、Hypothesis 与 Signal refs 恢复。
  • 草稿保存真实检索引用和失效反证，但不自动升级事实。
形成的用户旅程

Alert → Ask → 研究任务 → Agent Proposal → 人工保存草稿 → 再次确认或等待，整个过程可恢复、可审计、可继续。

09 · PRODUCT DELIVERY MAP

从“保住旧系统”到“形成学习闭环”的完整建设顺序

这是应用能力之间的依赖关系，不是每日完成状态。哪些切片已经通过，以上方动态快照和最近验收记录为准。

  1. R0

    冻结基线

    保留旧 CLI、摄入、Wiki、Ask 与 Research OS 能力，先立兼容和写入边界。

  2. R1

    六个领域契约

    建立 schema、校验器与只读仓储，让非法日期、单位、状态和无来源记录被拒绝。

  3. R2

    Signal Inbox

    把多种信源统一成 typed signal，同时保留来源差异、cursor、增量 chunk 与 firstSeenAt。

11 · HONEST LIMITS

公开页面刻意不展示什么

绝不公开

本地绝对路径、Cookie/token/password、Provider 原始响应、会员页、原文材料、未提交文件名、研究草稿正文。

只公开统计

分支短哈希、ahead/behind、变更文件数量、切片标题、测试数量与验收布尔状态。

不会自动宣称完成

任何能力只有在受控切片留下测试、构建或浏览器验收证据后，才进入动态进度；没有证据就保持未确认。

准确说法：这个站点报告“哪些纵向切片已经留下可验证证据”，而不是根据代码数量或 Agent 的自我判断宣布整个产品完成。

半套状态不能推进 checkpoint。

自动化就绪不等于生产已启用。

草稿固定 refs 与 gap，但不改变 Signal OS 权威。
